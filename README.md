# Автоматизация тематического кодирования качественных интервью в социологических исследованиях

## Команда
Львова Полина, Андреева Валентина, Чукавин Максим

## Актуальность
При работе с качественными социологическими данными, такими как интервью, исследователи сталкиваются с огромным количеством длительной работы, которую необходимо выполнять человеку. В частности, это касается кодирования интервью. Чаще всего перед исследователем стоит задача разметить релевантные поставленной теме части интервью, а также вынести из них коды – ключевые идеи размеченных частей. В качественном анализе существуют открытое и закрытое кодирование: в первом случае релевантный участок текста и коды подбираются индивидуально для каждого текста, а во втором части текст размечаются кодами из предварительно составленного набора, как правило, на основе существующих теорий (Полухина, 2025).

## Цель
Автоматизировать процесс открытого кодирования в соответствии с темой исследования и разметки релевантных кодам частей интервью.

## Задача модели – генерация кодов и цитат

**Вход:** текст интервью + тема исследования

**Выход:** список кодов и релевантных цитат

Кодирование интервью – пример задачи суммаризации текста, но важная особенность нашей задачи в том, что коды должны не только передавать наполнение текста, но и быть полезными при дальнейшем теоретическом анализе (Полухина, 2025). На момент создания данного проекта не найдено публикаций об открытом кодировании социологических интервью с помощью LLM: в этой сфере ИИ еще не в полной мере стал нормой.

Кодирование интервью вручную часто выполняется в 3 этапа: поиск релевантных участков текста, разметка кодами, суммаризация кодов (объединение похожих) (Полухина, 2025). При автоматизации кодирования мы планируем выполнить все три за одно применение модели.

## Данные
149 анонимизированных интервью из лаборатории ВШЭ СПб “Центр молодежных исследований”. Интервью собраны в рамках различных исследований лаборатории. Все интервью являются глубинными, содержащими широкий спектр вопросов о респонденте и теме исследования. Длительность одного интервью составляет 1-1.5 часа. Одно интервью закодировано и размечено лабораторией в соответствии с внутренними стандартами.
Более подробный анализ данных предоставлен в файле Eda_interviews.ipynb

## Архитектура для задачи

**Модель для дообучения**

- Важные условия для выбора нашей модели:
- Есть открытый исходный код на HuggingFace; наши данные не будут использоваться для дообучения коммерческих LLM
- Поддерживает русский язык
- Небольшой размер модели, чтобы с ней можно было работать в Google Colab
- Большое контекстное окно (необходимо, чтобы модель помнила предыдущий текст интервью во время обработки)
- Специфичные навыки (поиск в Интернете, написание кода) от модели не требуются

Таким образом, для решения нашей задачи мы будем дообучать следующие модели, после чего сравним их качество:
- **Qwen3.5-3B:** https://huggingface.co/Qwen/Qwen2.5-3B-Instruct
- **Qwen2.5-7B:** https://huggingface.co/Qwen/Qwen2.5-7B-Instruct

Первая модель легче и быстрее, с ней точно можно будет работать в Google Colab, ее контекстное окно в разы больше второй. Однако, вторая модель, предположительно, даст более точные результаты по сравнению с первой за счет большего количества параметров и специализации на решении сложных аналитических задач через рассуждения. Обе модели поддерживают русский язык и обучены на выполнение инструкций.

## Квантизация модели и размер батча
**8-битная** и **4-битная** квантизация будет использована для сокращения используемой памяти. Ввиду ограничений памяти, более точной квантизации соответствует меньший размер батча: 1 и 2 экземпляра соответственно, а также модель с меньшим количеством параметров: 3В и 7В соответственно.

## Дообучение модели
**LoRA (Low-Rank Adaptation)** дообучает LLM для суммаризации, замораживая веса исходной модели и внедряя в её слои малые обучаемые матрицы низкого ранга. Этот метод позволяет сократить число обучаемых параметров, снижая требования к видеопамяти. LoRA будет использоваться для дообучения 3В и 7B моделей.

**PPO (Proximal Policy Optimization)** применяется в рамках RL для тонкой настройки LLM под человеческие предпочтения. PPO-дообучение использует обученную на парах предпочтений Reward Model (RM), которая оценивает качество генерируемых саммари по фактологической точности и релевантности. Алгоритм PPO итеративно обновляет политику модели, максимизируя оценку RM при контроле расхождения с исходной моделью через KL-дивергенцию. Этот подход важен для кодирования, т.к. позволяет экспертно оценить теоретическую полезность кодов (см. подробнее в разделе Метрики). PPO требует больших объемов памяти, поэтому с ним будет обучаться только 3В модель.

## Стратегии генерации
Мы выбрали детерминированные стратегии генерации для сравнения моделей, чтобы избежать слишком большой отход от предобученного состояния: beam search, greedy search и beam search с доработанными параметрами.

## Правильные ответы
Для проверки качества модели нам будут необходимы верные ответы для модели: коды и соответствующие им части текста из транскриптов интервью. Так как транскрипты интервью были предварительно анонимизированы и лаборатория предоставила одно закодированное и размеченное интервью в соответствии со внутренними стандартами, мы прикрепим этот шаблон в самую мощную на момент проведения исследования LLM (DeepSeek-V3.2) и попросим закодировать и разметить остальные интервью. Далее мы проверим некоторые кодировки на качество вручную, чтобы убедиться в их качестве, и будем оценивать нашу модель в соответствии с ними.

## Метрики
Задача открытого кодирования сложна для оценки, так как коды выбираются не из фиксированного списка, и задачу нельзя свести к классификации. Для оценки выходов модели мы используем две компоненты: автоматическую и экспертную. Ввиду того, что объем текстов огромен для команды из трех человек, и положительных отзывах в ЦМИ о работе LLM как кодировщика, экспертная оценка будет осуществляться с помощью LLM (openai/gpt-oss-120b:free, 120B параметров).

**Машинная компонента: BERTScore.**
BERTScore — метрика, основанная на контекстуальных эмбеддингах. Для каждого токена в сгенерированном и эталонном коде вычисляется косинусная близость их векторных представлений, полученных с помощью трансформерной модели. Затем через процедуру жадного сопоставления (greedy matching) рассчитывается итоговая F1-мера, которая и выступает в качестве числовой оценки. Таким образом, BERTScore штрафует не за отличие в форме слова, а смысловую разницу кода и эталона. Метрика имеет готовые библиотечные реализации.

**Экспертная компонента: оценка с участием LLM.**
Для каждого предсказанного кода модель оценивает его по трём параметрам:
- Релевантность. Насколько код соответствует содержанию фрагмента интервью с учётом заявленной темы исследования.
- Когерентность. Является ли формулировка кода грамматически корректной и стилистически приемлемой для последующего анализа и включения в отчет.
- Теоретический инсайт. Степень соответствия кода концептуальным ожиданиям и теоретической чувствительности исследователя.

Оценки выставляются по шкале от 0 до 1, затем усредняются по всем трём параметрам и нормируются на общее количество закодированных фрагментов. Итоговое значение суммируется с машинной метрикой.
