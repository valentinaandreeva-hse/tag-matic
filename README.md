# tag-matic
tag-matic (automatic tagging) — проект, реализованный в рамках курса майнора ИАД, по автоматизации тематического кодирования качественных социологических интервью с помощью моделей генерации кодов и разметки текста. Разработан командой: Андреева Валентина, Львова Полина, Чукавин Максим — для упрощения работы исследователей ВШЭ СПб.

## Проект: Автоматизация тематического кодирования качественных интервью в социологических исследованиях

**Команда:** Львова Полина, Андреева Валентина, Чукавин Максим


### Актуальность

При работе с качественными социологическими данными, такими как интервью, исследователи сталкиваются с огромным количеством длительной работы, которую необходимо выполнять человеку. В частности, это касается кодирования интервью. Чаще всего перед исследователем стоит задача разметить релевантные поставленной теме части интервью, а также вынести из них коды - ключевые идеи размеченных частей. В качественном анализе существуют открытое и закрытое кодирование: в первом случае релевантный участок текста и коды подбираются индивидуально для каждого текста, а во втором части текст подвергается разметке кодами из предварительно составленного набора (чаще всего, на основе существующих теорий).

### Цель

Автоматизировать процесс выделения кодов в соответствии с темой исследования и разметки релевантных кодам частей интервью.

### Задачи

1) **Генерация кодов** (выполняется только в том случае, если у исследователя заранее нет списка кодов)

_Вход:_ текст интервью + тема исследования

_Выход:_ список кодов

2) **Разметка текста**

_Вход:_ текст интервью + список кодов
  
_Выход:_ размеченный текст в формате <код>цитата</код>

### Данные

149 анонимизированных интервью из лаборатории ВШЭ СПб “Центр молодежных исследований”. Одно из интервью закодировано и размечено лабораторией в соответствии с внутренними стандартами.

Более подробный анализ данных предоставлен в Eda_interviews.ipynb

## Архитектура для задачи

### Модель для дообучения

Важные условия для выбора нашей модели:
+ с **HuggingFace** - есть открытый исходный код; наши данные не будут использоваться для дообучения модели
+ поддерживает **русский язык**
+ **небольшой размер** модели, чтобы с ней можно было работать в Google Colab
+ **большое контекстное окно** (необходимо, чтобы модель помнила предыдущий текст интервью во время обработки)
+ конкретные tools необязательны: в нашей задаче необходима в основном генерация текста, интеграция с внешними системами для решения специализированных задач не требуется

Таким образом, для решения нашей задачи мы будем дообучать следующие модели, после чего сравним их качество:

1) **Qwen3.5-2B:** https://huggingface.co/Qwen/Qwen3.5-2B

2) **DeepSeek-R1-Distill-Qwen-7B:** https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-7B

Первая модель быстрее, с ней точно можно будет работать в Google Colab, так как она небольшая, и ее контекстное окно в разы больше второй. Однако, вторая модель, предположительно, даст более точные результаты по сравнению с первой за счет большего количества параметров и специализации на решении сложных аналитических задач через рассуждения. Также, несмотря на то, что обе модели поддерживают русский язык, Qwen изначально был настроен на множество языков, тогда как Deepseek только дообучался под языки помимо английского и китайского, что может привести к тому, что Qwen справится с задачей кодирования русскоязычных интервью лучше. Поэтому необходимо протестировать обе модели и далее выбрать лучшую.

#### Стратегии генерации

Beam Search с нормализацией длины, так как в кодировании интервью необходимо получить не разнообразие ответов, а постоянные информативные надежные коды.
Также, для скорости мы попробуем использовать Greedy Search и сравнить результат с Beam Search.

#### Квантизация модели

8-битная или 16-битная квантизация будет использована для сокращения используемой памяти

### Дообучение модели

LoRA: так как в данных лаборатории больше тысячи примеров, и LoRA в таком случае будет давать наилучшее качество с низким потреблением GPU за счет представления матрицы весов как произведения двух матриц

#### Правильные ответы

Для проверки качества модели нам будут необходимы верные ответы для модели: коды и соответствующие им части текста из транскриптов интервью. Так как транскрипты интервью были предварительно анонимизированы и лаборатория предоставила одно закодированное и размеченное интервью в соответствии со внутренними стандартами, мы прикрепим этот шаблон в самую мощную на момент проведения исследования LLM и попросим закодировать и разметить остальные интервью. Далее мы проверим некоторые кодировки на качество вручную, чтобы убедиться в их качестве, и будем оценивать нашу модель в соответствии с ними.

### Метрики

Задача открытого кодирования сложна для оценки, так как коды выбираются не из фиксированного списка, и задачу нельзя свести к классификации. Для оценки выходов модели мы используем две компоненты: автоматическую и экспертную. Ввиду того, что объем текстов огромен для команды из трех человек, и положительных отзывах в ЦМИ о работе LLM как кодировщика, экспертная оценка будет осуществляться с помощью модели (например, DeepSeek-V4-Lite, около 200B параметров).

1) **Машинная компонента: BERTScore**.

BERTScore — метрика, основанная на контекстуальных эмбеддингах. Для каждого токена в сгенерированном и эталонном коде вычисляется косинусная близость их векторных представлений, полученных с помощью трансформерной модели. Затем через процедуру жадного сопоставления (greedy matching) рассчитывается итоговая F1-мера, которая и выступает в качестве числовой оценки. Таким образом, BERTScore штрафует не за отличие в форме слова, а смысловую разницу кода и эталона. Метрика имеет готовые библиотечные реализации.

2) **Экспертная компонента: оценка с участием LLM**.

Для каждого предсказанного кода модель оценивает его по трём параметрам:
_Релевантность._ Насколько код соответствует содержанию фрагмента интервью с учётом заявленной темы исследования.
_Когерентность._ Является ли формулировка кода грамматически корректной и стилистически приемлемой для последующего анализа и включения в отчет.
_Теоретический инсайт._ Степень соответствия кода концептуальным ожиданиям и теоретической чувствительности исследователя.

Оценки выставляются по шкале от 1 до 5, затем усредняются по всем трём параметрам и нормируются на общее количество закодированных фрагментов. Итоговое значение суммируется с машинной метрикой.
